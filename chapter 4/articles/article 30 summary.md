# Art. 30 GDPR – Records of Processing Activities (RoPA)

## Summary

Article 30 requires controllers and processors to maintain a written **Record of Processing Activities (RoPA)** and make it available to the supervisory authority on request. The records serve as a central accountability and transparency tool.

### Controller RoPA — Required Content

| Field | Detail |
|-------|--------|
| Controller identity | Name and contact details of the controller, joint controller(s), representative, and DPO. |
| Purposes | The purposes of each processing activity. |
| Categories of data subjects | Description of the categories of individuals whose data are processed. |
| Categories of personal data | Description of the types of personal data processed. |
| Recipients | Categories of recipients, including third-country recipients and international organisations. |
| Third-country transfers | Identification of the destination country/organisation and transfer safeguards (Art. 49 documentation). |
| Retention | Envisaged time limits for erasure of each category of data (where possible). |
| Security measures | General description of Art. 32(1) technical and organisational security measures (where possible). |

### Processor RoPA — Required Content

| Field | Detail |
|-------|--------|
| Processor identity | Name and contact details of the processor(s), each controller, representative(s), and DPO. |
| Categories of processing | Categories of processing carried out on behalf of each controller. |
| Third-country transfers | As above, with safeguard documentation. |
| Security measures | General description of Art. 32(1) TOMs (where possible). |

### Key Rules

| Rule | Detail |
|------|--------|
| **Written form** | Records must be in writing, including electronic form. |
| **Availability** | Must be made available to the supervisory authority on request. |
| **SME exemption** | Organisations with fewer than 250 employees are exempt unless: processing is likely to result in a risk to rights/freedoms; processing is not occasional; or processing includes special categories (Art. 9) or criminal data (Art. 10). |

## Todo List

- [ ] Create or review the **controller-side RoPA**, ensuring all mandatory fields are completed for every processing activity.
- [ ] Create or review the **processor-side RoPA** for all processing carried out on behalf of controllers.
- [ ] Implement a **RoPA maintenance process**: assign ownership per processing activity; update the RoPA whenever activities change.
- [ ] Store the RoPA in **written (electronic) form** accessible to the DPO and data protection team.
- [ ] Prepare the RoPA to be **submitted to the supervisory authority on request** without delay.
- [ ] Assess whether the **SME exemption** applies; document the assessment and set reminders to reassess if headcount or processing scope changes.
- [ ] Link RoPA entries to **DPIAs, DPAs, and legal basis documentation** to create a complete accountability file per processing activity.
- [ ] Conduct an annual **RoPA audit** to identify outdated, missing, or inaccurate entries and remediate.
- [ ] Ensure RoPA entries for **third-country transfers** reference the correct Art. 46 or Art. 49 safeguard mechanism.
