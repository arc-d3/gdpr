# Art. 32 GDPR – Security of Processing

## Summary

Article 32 requires both **controllers and processors** to implement technical and organisational measures to ensure a level of security appropriate to the risk. The required level is determined by balancing risk against the state of the art and implementation costs.

### Required Security Measures (non-exhaustive)

| Measure | Detail |
|---------|--------|
| **Pseudonymisation and encryption** | Of personal data where appropriate to the risk. |
| **Confidentiality, integrity, availability, resilience** | Ongoing ability to ensure these properties for processing systems and services. |
| **Recovery capability** | Ability to restore availability and access to personal data in a timely manner after an incident. |
| **Regular testing** | Process for regularly testing, assessing and evaluating the effectiveness of the security measures. |

### Risk Assessment Factors

| Factor | Examples |
|--------|---------|
| **Risks to assess** | Accidental or unlawful destruction, loss, alteration, unauthorised disclosure of or access to personal data. |
| **Calibration** | Nature, scope, context, purposes of processing; likelihood and severity of risk to rights/freedoms. |
| **State of the art** | Available technologies and their cost must be considered. |

### Additional Rules

| Rule | Detail |
|------|--------|
| **Compliance evidence** | Adherence to an approved code of conduct (Art. 40) or certification mechanism (Art. 42) may be used to demonstrate compliance. |
| **Personnel** | Controller and processor must ensure that persons acting under their authority process data only on instructions (Art. 32(4) / Art. 29). |

## Todo List

- [ ] Conduct an **information security risk assessment** mapped to processing activities, identifying likelihood and severity of data security incidents.
- [ ] Implement **encryption at rest and in transit** for all personal data processing, calibrated to data sensitivity.
- [ ] Implement **pseudonymisation** where technically feasible to reduce exposure in the event of a breach.
- [ ] Test and document **availability, integrity, and resilience controls** for all systems processing personal data.
- [ ] Document and test a **data recovery procedure** capable of restoring personal data access in a timely manner after an incident.
- [ ] Establish a **regular security testing programme** (vulnerability scanning, penetration testing, security audits) and record results.
- [ ] Include Art. 32 security obligations in **DPAs with processors** and verify compliance through assessments or audits.
- [ ] Ensure **access controls and need-to-know principles** are applied so staff only access personal data authorised by the controller.
- [ ] Assess whether an **approved code of conduct** (Art. 40) or **certification** (Art. 42) in the security domain is appropriate.
- [ ] Review security measures following any significant change to processing activities or infrastructure.
